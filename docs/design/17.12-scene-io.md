# 17.12 場景讀寫(ludens-engine #82)

2026-11-02 決定:編輯器放在 ludens-shell,場景檔案格式由 ludens-shell 定義(ludens-shell #9)。
引擎的責任是格式需要的 API 與 parity,不是檔案格式。

## 場景不是快照

| | 場景(`embed/scene_io.mojo`) | 決定論快照(`EmbedWorld.save`) |
|---|---|---|
| 內容 | 設定 + 作者資料(物體的形狀、質量、姿態、速度、碰撞層、材質、使用者資料、21 個物理屬性) | 全部模擬狀態,含 warm-start 快取、睡眠計時、tick |
| 用途 | 編輯、diff、版本化、prefab 覆寫 | 回放、回滾、存檔 |
| 穩定性 | 欄位以路徑命名,新增欄位不破壞舊檔 | 位元組布局,隨引擎版本變 |

兩條路徑建出的世界必須逐位相同(從作者資料開始、tick 0):`tests/test_scene_io.mojo` 在 tick 0 與 300 tick 後比雜湊。

## 介面

- `SceneDoc`:型別化的記憶體文件。
- `scene_to_fields` / `scene_from_fields`:文件 ⇄ (路徑, 規範文字) 列。宿主的檔案格式只需要讀寫這張表,不必認得每個欄位。
- `scene_diff` / `scene_apply`:列級差異與套用。prefab 實例 = prefab 的列 + 實例的差異。差異記錄 `before`,底稿不符就拒絕。

## 取捨

- 實數寫成 `Float64` 文字:往返不失真。代價是比快照慢約兩個數量級(進度註有數字)。
- 物體以位置定址(`body.3.pos.x`):中間插入一個物體,後面全部顯示為變更。以穩定 id 定址需要場景裡有 id,屬格式層的決定(ludens-shell #9)。
- 匯入不重新正規化旋轉:正規化會改變位元,破壞與快照的 parity;不是單位四元數的輸入拒絕。
- 不支援的內容拒絕並指名,不靜默丟棄。
